# AGENTS.md — この案件の共通ルール

このファイルは、この案件フォルダで作業するAIエージェントと人間の共通ルールです。
作業を始める前に必ず読んでください。

## フォルダの使い方

| フォルダ | 置くもの | ルール |
|---|---|---|
| `input/` | 作業の参照資料（ソースコード・設計書・受領資料など） | 置き方は自由。**中身は変更しない**。詳細は `input/README.md` |
| `output/` | 成果物と、その作り方 | **成果物ごとにフォルダを分ける**。詳細は `output/README.md` |

成果物フォルダの中身:

```
output/NN_成果物名/
├── instruction.md   … 作業指示書（必須は 目的・インプット・成果物・完了条件）
├── work/
│   ├── scripts/     … 調査・抽出・変換に使ったスクリプト
│   └── data/        … 中間データ・抽出結果
└── （成果物ファイル）
```

## 作業の進め方

### 質問・相談だけのとき
- その場で回答する。フォルダやファイルは作らない。

### 成果物を作るとき
- **必ず `output/README.md` の「成果物を作る手順（AI向け）」に従う**
- 流れ: 計画を1回で示して合意 → `output/NN_成果物名/` を作る → `instruction.md` を書く → 作業 → 完了条件で確認して報告
- 簡単な作業に、過剰な確認や計画を求めない

### input/ の整理を手伝うとき
- 利用者が自分で作ったフォルダ構成は**そのまま尊重する**。標準構成に合わせるための作り直しは提案しない
- 提案するのは、`input/` の直下にファイルが散らばっているとき、または利用者に頼まれたときだけ（毎回は聞かない）
- 提案は、利用者の既存の構成があればそれに合わせ、なければ `input/README.md` の「整理の参考にするフォルダ構成」に沿う
- 移動・フォルダ名の変更は**利用者の承認を得てから**行う。移動したら、参照している `instruction.md` のパスも直す

## 共通ルール

- インプット（`input/`）のファイルの中身は変更しない（置き場所の整理は承認があればよい）
- 作業指示書・作成過程・成果物をセットで、成果物フォルダの中に置く
- 再実行に必要なスクリプトや中間データは `work/` に残す。不要な一時ファイルは残さない
- 調査・レビュー結果には**根拠と参照元**を書き、**事実と推測を区別**する（書き方は下の「根拠と確度の書き方」）
- 既存ファイルを無断で上書き・削除しない
- 社内の情報セキュリティルールを守る
- 成果物の最終確認は人間が行う

## 根拠と確度の書き方

調査・レビュー・設計の成果物では、記述ごとに**確度**と**根拠**を書く。
チャットでの回答でも、根拠（ファイル名・行）はできるだけ添える（ラベルは任意）。

### 確度ラベル

| ラベル | 意味 |
|---|---|
| `[事実]` | 資料・ソースで確認できた |
| `[推測]` | 資料から推測した。確認はしていない（推測の理由も書く） |
| `[未確認]` | 分からない、または確認できなかった（何を確認すればよいかも書く） |

- `[事実]` は**調べたインプットの範囲での事実**。「〜はない」「〜しない」のように、調べていない範囲まで言い切る結論は `[事実]` にせず、範囲を書く
  - 例: `[事実] input/src/ 内に Release の呼び出し元はない` ／ `[未確認] 他の層で Release を呼んでいるか`
- 成果物の冒頭に「調査範囲（見たインプット）」を書く

### 根拠の書き方

案件フォルダからの相対パスで書く。

| 資料 | 書き方の例 |
|---|---|
| ソースコード | `input/src/Order.cs:120`、`input/src/Order.cs:120-145` |
| Excel | `input/基本設計書.xlsx「受注」シート B12` |
| Word / PDF | `input/要件定義書.pdf p.15「3.2 受注処理」` |
| 議事録・メール | `input/議事録_20261120.md「決定事項」` |
| 利用者からの口頭情報 | `（利用者より 2026-11-28）` |

### 記述例

```
- [事実] 受注確定時に在庫引当を行う（input/src/Order.cs:120-145）
- [推測] 夜間バッチでも同じ処理を呼んでいる可能性がある。呼び出し元に Batch という名前のクラスがあるため（input/src/Batch/Nightly.cs:30）
- [未確認] キャンセル時に引当を戻すか。該当する処理が見つからない。担当者への確認が必要
```

- Excel など表形式の成果物では、「確度」「根拠」の列を設ける
