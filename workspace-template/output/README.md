# output/ — 成果物と、その作り方

成果物ごとにフォルダを作ります。成果物だけでなく「どう作ったか」も一緒に残します。

```
output/
├── _template/            … ひな形（直接編集しない）
├── 01_現行機能調査/
│   ├── instruction.md    … 作業指示書
│   ├── work/scripts/     … 使ったスクリプト
│   ├── work/data/        … 中間データ
│   └── 現行機能調査結果.xlsx
└── 02_設計書レビュー/
    └── ...
```

## 使い方（人間向け）

AIに「〇〇を調査したい」「〇〇のレビューをしたい」のように頼むだけです。
AIが下の手順で、成果物フォルダと作業指示書（`instruction.md`）を作ってから作業します。

自分で作るときは、`_template/` をコピーして `NN_成果物名/` に名前を変え、`instruction.md` を埋めてください。

## なぜこうするのか

- 成果物と作業指示の関係が一目でわかる
- インプットが変わったとき、同じ手順で作り直せる
- 他の人（や別のAI）に引き継げる
- ファイルがあちこちに散らからない

---

## 成果物を作る手順（AI向け）

AIは、成果物を作るときに**この手順に従う**こと。

### 0. 成果物フォルダが必要か判断する

- **必要**: ファイルとして残す成果物を作るとき（調査結果、設計書、レビュー結果、テスト仕様書、修正したソースなど）
- **不要**: 質問への回答、相談、その場で終わる短い説明。チャットで答えるだけにする
- **既存の続き**: 依頼が既存の成果物フォルダの続き・作り直しなら、新しいフォルダは作らず、そのフォルダで作業する（どのフォルダか迷ったら利用者に聞く）

### 1. 計画を示して合意する（確認は1回にまとめる）

次の5点を**1つのメッセージ**で示し、利用者の返事を待つ:

```
次の内容で進めてよいですか？
- フォルダ: output/NN_成果物名/
- 目的: …
- インプット: input/…（足りない資料があれば、ここで聞く）
- 成果物: ファイル名（形式）
- 完了条件: …
```

- 簡単な作業（資料が少なく、すぐ終わるもの）なら、1〜2行に縮めてよい。例:「`output/03_〇〇調査/` に `〇〇調査結果.md` を作ります。進めてよいですか？」
- 質問を何度にも分けない
- 「OK」だけの返事なら、計画どおり（追加の資料なし）で進める。修正が返ってきたら、反映して進める（再確認は不要）

### 2. フォルダを作る

- **番号（NN）**: `output/` 直下の `2桁数字_` で始まるフォルダの最大番号 + 1。なければ `01`
- **名前**: 成果物を表す短い日本語（番号を除いて**20文字以内**が目安。例: `03_受注画面の影響範囲調査`）。空白や記号（`/ \ : * ? " < > |`）は使わない
- `_template/` を**コピーコマンドで**コピーする
  - PowerShell: `Copy-Item -Path output\_template -Destination output\NN_成果物名 -Recurse`（コピー先が存在しないことを先に確認する）
  - ターミナルが使えない場合だけ、同じ構成（`instruction.md`、`work/scripts/.gitkeep`、`work/data/.gitkeep`）をファイル作成ツールで作る。`instruction.md` はテンプレートの見出しを変えない
- 同じ名前のフォルダがすでにあれば、作らずに利用者に伝える
- `work/` の `.gitkeep` は、中身が空でも消さない

### 3. instruction.md を書く

- 手順1で合意した内容で、**必須の4項目**（目的・インプット・成果物・完了条件）を埋める
- 任意の項目は、作業が大きいとき・引き継ぎが想定されるときだけ書く。不要な項目は消してよい
- 状態は「作業中」のまま（テンプレートの初期値）

### 4. 作業する

- `input/` のファイルの中身は変更しない。加工が必要なら `work/data/` にコピーしてから加工する
- 使ったスクリプトは `work/scripts/` に、中間データは `work/data/` に置く
- 作業中だけ使った一時ファイルは、終わったら消す
- 作業の進め方に関するメモ（使った方法、つまずいた点、再実行の注意）は `instruction.md` の「作業メモ」に書く。調査で分からなかったこと（`[未確認]`）は**成果物のほうに**書く

### 5. 確認して報告する

- `instruction.md` の完了条件を1つずつ確認し、AIが確認できたものに `[x]` を付ける。「人間による最終確認」には付けない（利用者が付ける）
- 根拠・事実と推測の書き方が `AGENTS.md` のルールに沿っているか確認する
- 状態を「確認待ち」にし、次の形で報告する:

```
成果物ができました: output/NN_成果物名/成果物ファイル
- 概要: …（3行以内）
- 未確認事項: …（なければ「なし」）
- 確認をお願いしたい点: …
```

- 利用者が確認を終えたと伝えたら、状態を「完了」にし、「人間による最終確認」に `[x]` を付ける
