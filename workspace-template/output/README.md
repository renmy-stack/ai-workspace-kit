# output/ — 成果物と、その作り方

成果物ごとにフォルダを作ります。成果物だけでなく「どう作ったか」も一緒に残します。

```
output/
├── _template/            … ひな形（直接編集しない）
├── 01_現行機能調査/
│   ├── instruction.md    … 作業指示書
│   ├── work/scripts/     … 使ったスクリプト
│   ├── work/data/        … 中間データ
│   └── 現行機能調査結果.xlsx
└── 02_設計書レビュー/
    └── ...
```

## 新しい成果物を作るとき

1. `_template/` をコピーし、`NN_成果物名/` に名前を変える（NN は既存の最大番号 + 1、2桁）
   - AIに「〇〇を作りたい」と頼めば、AIがこの手順で作ります
2. `instruction.md` を埋める（AIと相談しながらでよい）
3. 作業する
4. `instruction.md` の完了条件で確認する

## なぜこうするのか

- 成果物と作業指示の関係が一目でわかる
- インプットが変わったとき、同じ手順で作り直せる
- 他の人（や別のAI）に引き継げる
- ファイルがあちこちに散らからない
